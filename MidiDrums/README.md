Due to copyright reasons you need to add your own MIDI drum grooves here.
There is a primitive example here (Linear Fusion), exchange it with your own collection.

Organize grooves one folder per genre/style, each holding `.mid` files with an optional
matching `.json` sidecar of the same base name:

```
MidiDrums/
  <Genre>/
    <name>.mid
    <name>.json   (optional)
```

Sidecar JSON fields (all optional, as seen in the shipped example):

```
{
  "idealBpm": 120.0,
  "rhythm": { "feel": "even", "timeSignature": "6/8" },
  "variation": 1,
  "section": "verse",
  "dominantSounds": ["hihat", "snare"],
  "variesBy": "cymbal"
}
```

`dominantSounds` and `variesBy` are written by `analyze_variations.py` (see below) and
are not free-form: their values are always drawn from the fixed category list `rimshot`,
`snare`, `tom`, `hihat`, `cymbal`, `percussion`. A consumer (the looper, or any other
tool searching this library) should match against these category names directly rather
than re-deriving them from raw MIDI note numbers.

## Filename convention

Most genre folders were generated by `populate_from_worthy.py` (see that script's
docstring for the full source-format details) from a curated groove list. Filenames
follow `{feel}_{timesig}_{subversion}_{section}_v{variation}`, with any segment
omitted when the source groove has no data for it (e.g. some packs carry no feel or
time signature, and a few have no section at all):

- feel: `str` straight, `swg` swing, `shf` shuffle
- section: `v` verse, `c` chorus, `b` beats
- timesig: as-is with `/` replaced by `#` (e.g. `6/8` -> `6#8`)
- subversion: an integer starting at 1 that disambiguates distinct source grooves
  which would otherwise share the same `{feel}_{timesig}_{section}` name (assigned in
  ascending-BPM order)
- variation: the original source variation number (not renumbered), so a groove's
  files may skip numbers, e.g. `_v1 _v2 _v4 _v5`

`dominantSounds` and `variesBy` group these into six broader categories: `rimshot`,
`snare`, `tom`, `hihat`, `cymbal`, `percussion` (kick is excluded from both fields,
since it is present in nearly every groove). A library consumer (the looper, a
groove-search feature, ...) should match against these category names - e.g. "a
kick-heavy groove with rimshots" means `dominantSounds` includes `"rimshot"`.
