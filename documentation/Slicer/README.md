# Slicer exploration harness

A small offline program for exploring, testing and fine-tuning the loop
`AbacDsp::Slicer` (`src/includes/Analysis/Slicer.h`) against hand-labelled
audio. It loads a WAV file, runs a chosen slicing algorithm, and compares the
detected slice boundaries with a manual reference, printing detection
statistics.

This lives under `documentation/` as a loose experimentation tool, not a unit
test. Use it to tune thresholds and window sizes before wiring values into the
looper.

## Building

Enabled behind the `EXPLORE_STUFF` CMake option:

```bash
mkdir -p build && cd build
cmake -DEXPLORE_STUFF=ON -DCMAKE_BUILD_TYPE=Release ..
cmake --build . --target SlicerExplore
```

## Running

```bash
./SlicerExplore path/to/guitar#1.wav documentation/Slicer/settings.example.txt
```

- The first argument is the audio file (any format `AudioFile` supports).
- The second argument is an optional settings file (defaults are used if
  omitted).

### Sample fixture

`AudioSamples/artificial-percussion.wav` (plus its `.txt` ground truth) is a
small synthetic fixture: six sharp-attack decaying tone bursts at known onsets.
It is regenerated by the `GenerateArtificialSample` target:

```bash
cmake --build . --target GenerateArtificialSample
./GenerateArtificialSample path/to/documentation/Slicer/AudioSamples
```

The argument is the output directory (default `AudioSamples`). Output is
deterministic, so rerunning reproduces the committed files byte for byte.

### Ground-truth file

For an audio file `guitar#1.wav` the harness reads `guitar#1.txt` next to it
(same stem, `.txt` extension). Each non-comment line describes one manually
placed slice:

```
# name          begin(samples)   length(samples)
kick             0                12000
snare            12000            9500
hat              21500            6000
```

- `name` is a label used only for the report; it may contain spaces.
- `begin` and `length` are in samples.
- Fields are separated by comma, semicolon or tab (so a name can hold spaces);
  a line with none of those separators falls back to whitespace splitting, and
  the name must then be a single token. `#` starts a comment.
- Only `begin` is used for onset matching; `length` is informational.

### Settings file

See `settings.example.txt` for the full list of keys and defaults. It selects
the detector (`transient`, `spectral`, `adaptive`, `grid`), the match
`tolerance`, and the tuning values passed into each detector.

- `transient` / `spectral` map straight onto `Slicer::TransientParams` /
  `Slicer::SpectralParams` in the core library.
- `adaptive` is a harness-local prototype (see Findings) that replaces the
  spectral detector's single global threshold with a locally adaptive one, to
  recover quiet ghost notes without flooding the loud passages with false
  positives.

## Findings

Tuning notes from the sample set in `AudioSamples/` (48 kHz), all measured with
the harness against the hand labels:

- `spectral.minGapFrames = 6000` (~125 ms) is the best no-regression setting for
  the plain spectral detector: it collapses guitar/bass strum double-triggers
  without dropping real hits.
- Lowering `spectral.relativeThreshold` does **not** recover ghost notes: their
  flux is below any usable global fraction of the peak, so it only manufactures
  false positives.
- Legato transitions are detected well by spectral flux: a pitch change produces
  flux even without an amplitude attack.
- The `adaptive` detector (`lambda = 2.5`) ties or beats the plain spectral
  detector on every sample file, driving guitar/bass false positives to zero and
  recovering ghost notes that stand out from their local neighbourhood. The
  very quietest ghosts still fall below the local floor and are missed.
- Parameter effects are non-monotonic (for example bass false positives swing
  6 -> 5 -> 0 as `lambda` goes 1.6 -> 2.0 -> 2.5), so tune across all files, not
  one at a time.
- Slice-start refinement (`refine.enabled = 1`) cuts mean onset-timing error
  2-3x on real material (guitar 425 -> 197, bass 417 -> 219 samples) and to ~1
  sample on the synthetic fixture, with **no** change to precision/recall since
  it only nudges onsets within the match tolerance. A 100 ms preroll is what
  makes it work, because the flux onsets sit late. It cannot fix legato slurs,
  which have no attack edge to snap to.
- Offset-transient rejection (the Python slicer's `_remove_offset_transients`)
  was prototyped and **rejected**: on top of the adaptive detector it only
  removes real onsets (legato, ghosts, trailing notes) without a precision gain
  to show for it. The adaptive threshold already handles the false positives it
  was meant to catch.

## Output

The report prints, for the chosen method:

- ground-truth vs detected slice counts,
- true / false positives, false negatives,
- precision, recall, F1 (onset matched within `tolerance`),
- mean and max absolute onset timing error (samples and ms),
- a per-slice table of label vs matched onset and the signed delta.

The implied boundary at frame 0 is excluded from matching, since a
hand-labelled transient never sits at the very start of the loop.
